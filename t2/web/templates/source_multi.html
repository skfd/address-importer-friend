Toronto's address-points dataset is one row per point, so it doesn't pack multi-values into a single tag the way OSM addr:housenumber does. Two list-shaped exceptions show up:

  • Range addresses ({{ '{:,}'.format(stats.ranges_total) }} rows, {{ (stats.ranges_total / stats.total_active * 100) | round(2) }}% of active) — a single point representing a span of housenumbers, encoded as N-M with structured lo_num / hi_num columns.
  • Half-numbers ({{ '{:,}'.format(stats.halves_total) }} rows) — addresses suffixed 1/2, e.g. 2455 1/2 Queen St E. Single addresses, not lists, but reported here as a sibling encoding quirk.

Letter sub-addresses (123A, 123B, …) are not lists — each is a single-row address with a sub-letter. They're not counted here.
